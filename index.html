Análisis del tráfico de red y detección de intrusiones

1 Introducción

La seguridad de las redes es una parte importante de la administración de sistemas. Los ordenadores, servidores y otros dispositivos se comunican continuamente y generan conexiones. La mayoría de estas comunicaciones son normales, pero algunas pueden estar relacionadas con errores o actividades sospechosas. Por este motivo, un administrador de sistemas necesita conocer el tráfico de la red y disponer de información que le ayude a detectar comportamientos poco habituales. El análisis de datos permite resumir muchos registros y localizar aquellos que conviene revisar con más detalle. En este proyecto utilizamos Python y Pandas para cargar, limpiar, explorar y analizar un conjunto de datos de detección de intrusiones descargado de Kaggle. Para representar los resultados empleamos Matplotlib, Seaborn y Plotly. El trabajo tiene un objetivo didáctico. No estamos desarrollando un sistema que bloquee ataques automáticamente, sino practicando el tratamiento de datos y aprendiendo a interpretar los resultados desde el punto de vista de un administrador de sistemas.

1.1 Objetivos

Los objetivos principales del trabajo son:

  • Cargar los archivos CSV y conocer su estructura.
  • Revisar los tipos de datos, los valores nulos y los registros duplicados.
  • Preparar algunas columnas para facilitar los cálculos.
  • Comparar conexiones normales con conexiones etiquetadas como anómalas.
  • Analizar protocolos, servicios y estados de conexión.
  • Utilizar concat(), groupby(), pivot_table(), loc e iloc.
  • Crear gráficos estáticos y un gráfico interactivo.
  • Proponer medidas básicas que podría aplicar un administrador de sistemas.

1.2 Preguntas que queremos responder

Durante el análisis intentaremos responder a las siguientes preguntas:

  1. ¿Cuántas conexiones aparecen clasificadas como normales y cuántas como anómalas?
  2. ¿Qué duración y volumen de datos tienen las conexiones?
  3. ¿Qué protocolos presentan una mayor proporción de registros anómalos?
  4. ¿Qué servicios acumulan más conexiones de cada tipo?
  5. ¿Existen conexiones que conviene revisar por su volumen de datos o por sus intentos fallidos de inicio de sesión?
  6. ¿Qué medidas podría proponer un administrador a partir de estos resultados? Estas preguntas nos sirven para decidir qué operaciones de Pandas y qué gráficos vamos a utilizar.

2 Descripción del conjunto de datos

El conjunto de datos utilizado es Network Intrusion Detection de Kaggle. Contiene registros que describen conexiones de red y diferentes características de cada conexión. En los archivos que hemos utilizado, el conjunto de entrenamiento tiene 25.192 filas y 42 columnas. El conjunto de prueba tiene 22.544 filas y 41 columnas. El archivo de entrenamiento incluye la columna class, mientras que el archivo de prueba no dispone de esa etiqueta.

2.1 ¿Qué representa cada fila?

Cada fila representa una conexión de red descrita mediante varias características. Algunas columnas indican la duración de la conexión o la cantidad de datos transferidos. Otras identifican el protocolo, el servicio o el estado de la comunicación. El archivo de entrenamiento incluye una columna llamada class, que permite distinguir las conexiones etiquetadas como normal de las etiquetadas como anomaly. En este informe las presentamos como Normal y Anómalo para que las tablas y los gráficos sean más fáciles de leer.

2.2 Columnas principales

No vamos a estudiar las 42 columnas con el mismo detalle. Nos centraremos en las que sirven para explicar mejor el comportamiento de las conexiones.

2.3 Relación con la Administración de Sistemas

Un administrador puede utilizar información de este tipo para conocer qué protocolos se utilizan, comprobar qué servicios reciben conexiones y localizar comportamientos diferentes de los habituales. Por ejemplo, muchas conexiones rechazadas podrían indicar un problema de configuración o intentos de acceso no válidos. Un volumen de datos elevado podría ser normal en una descarga, pero también puede justificar una comprobación si no corresponde con la actividad esperada. Por tanto, los datos sirven como una ayuda para investigar. No debemos interpretar una sola característica como una prueba definitiva de que se ha producido un ataque.

5 Exploración estadística (EDA)

EDA significa Exploratory Data Analysis, o análisis exploratorio de datos. Es la fase en la que observamos las características principales del conjunto para entender qué información contiene antes de extraer conclusiones. En este apartado calculamos varios resúmenes estadísticos y estudiamos la distribución de diferentes variables.

5.1 Distribución del tráfico normal y anómalo

Primero contamos cuántas conexiones hay de cada tipo. Después calculamos qué porcentaje representa cada grupo sobre el total.

Mostrar código 
conteo_trafico = datos["tipo_trafico"].value_counts()
porcentaje_trafico = datos["tipo_trafico"].value_counts(normalize=True) * 100
resumen_trafico = pd.DataFrame({
    "Conexiones": conteo_trafico,
    "Porcentaje (%)": porcentaje_trafico.round(2)
})
display(resumen_trafico)

tipo_trafico

La distribución está relativamente repartida entre las dos clases. Es útil para comparar ambos grupos, aunque no significa que esas proporciones se vayan a repetir en una red real.

6 Análisis avanzado con Pandas

En esta sección utilizamos las operaciones que solicita el profesor. Cada consulta responde a una pregunta práctica desde el punto de vista de la administración de sistemas.

6.1 Unir los archivos con concat()

El conjunto tiene un archivo de entrenamiento y otro de prueba. Vamos a unirlos verticalmente con concat() y añadiremos una columna para conservar la procedencia de cada fila.

Mostrar código 
train_concat = train.copy()
test_concat = test.copy()
train_concat["origen_datos"] = "Entrenamiento"
test_concat["origen_datos"] = "Prueba"
datos_combinados = pd.concat(
    [train_concat, test_concat],
    ignore_index=True,
    sort=False
)
print("Filas del conjunto combinado:", datos_combinados.shape[0])
print("Columnas del conjunto combinado:", datos_combinados.shape[1])
display(datos_combinados["origen_datos"].value_counts())
Filas del conjunto combinado: 47736
Columnas del conjunto combinado: 45
origen_datos
Entrenamiento    25192
Prueba           22544
Name: count, dtype: int64

concat() coloca las filas de un archivo debajo de las filas del otro. Como el archivo de prueba no contiene la columna class, Pandas crea esa columna en el resultado y deja valores nulos en las filas que proceden del archivo de prueba. Por eso, para comparar Normal y Anómalo utilizamos únicamente los registros etiquetados del entrenamiento. No debemos interpretar las filas sin etiqueta como tráfico anómalo.

8 Interpretación desde la Administración de Sistemas

Después de realizar los cálculos y las visualizaciones, podemos relacionar los resultados con algunas tareas habituales de un administrador de sistemas.

8.1 Revisar los protocolos

El análisis por protocolo muestra diferencias en el porcentaje de conexiones anómalas. ICMP presenta un porcentaje elevado en este conjunto, por lo que sería interesante revisar el uso que se hace de este protocolo y comprobar si la actividad es esperada. Esto no significa que haya que bloquear ICMP por completo. Este protocolo también se utiliza para diagnóstico de red, por ejemplo mediante herramientas como ping.

8.2 Revisar los servicios

La tabla dinámica permite observar qué servicios tienen más registros anómalos. Los servicios con más actividad sospechosa pueden revisarse para comprobar si están habilitados, si son necesarios y si tienen una configuración adecuada. Un administrador podría:

  • Deshabilitar servicios que no se utilicen.
  • Revisar los puertos asociados a servicios expuestos.
  • Comprobar los registros del servidor.
  • Restringir el acceso a servicios que solo deban utilizarse desde redes internas.

8.3 Investigar volúmenes de datos elevados

Una conexión con muchos bytes transferidos puede ser normal, por ejemplo durante una descarga o una copia de seguridad. Sin embargo, también podría justificar una revisión si no corresponde con la actividad habitual. Por eso, los registros seleccionados con loc() deben utilizarse como punto de partida para investigar, no como una lista automática de ataques confirmados.

8.4 Revisar errores y accesos

Las tasas de error y los intentos fallidos de inicio de sesión pueden ayudar a localizar problemas de conectividad o accesos que conviene revisar. Entre las acciones posibles están comprobar los registros de autenticación, verificar el estado de los servicios y revisar las reglas del firewall.

8.5 Medidas básicas que proponemos

A partir del análisis, proponemos algunas medidas sencillas:

  1. Mantener actualizados los sistemas operativos y los servicios de red.
  2. Desactivar servicios y puertos que no sean necesarios.
  3. Revisar los intentos fallidos de autenticación y establecer políticas de contraseñas adecuadas.
  4. Monitorizar el tráfico de los protocolos y servicios más utilizados.
  5. Configurar reglas de firewall acordes con las necesidades de la red.
  6. Utilizar herramientas IDS/IPS para ayudar a detectar actividad sospechosa. Estas medidas son recomendaciones generales. En una red real habría que adaptarlas a la infraestructura y comprobar su efecto antes de aplicarlas.

9 Conclusiones

El análisis ha permitido estudiar un conjunto de conexiones de red y comparar los registros clasificados como normales y anómalos. Con Pandas hemos cargado los archivos, comprobado su estructura, revisado valores nulos y duplicados, creado una nueva variable y realizado diferentes consultas. También hemos practicado operaciones importantes como concat(), groupby(), pivot_table(), loc() e iloc(). Los resultados muestran diferencias entre protocolos y servicios. En particular, ICMP presenta una proporción elevada de conexiones anómalas en este conjunto, y algunos servicios acumulan un número importante de registros de esa categoría. Los gráficos facilitan la interpretación de las tablas y permiten localizar patrones que podrían ser interesantes para un administrador de sistemas. Como propuestas de mejora, consideramos importante mantener los servicios actualizados, revisar las reglas del firewall, controlar los accesos y utilizar herramientas de monitorización y detección de intrusiones (IDS/IPS).

9.1 Limitaciones del análisis

Hay que tener en cuenta algunas limitaciones:

  • Los datos pertenecen a un conjunto preparado para estudiar la detección de intrusiones y no representan necesariamente el tráfico actual de una red real.
  • El archivo de prueba no tiene la etiqueta class, por lo que no podemos clasificar directamente sus conexiones como normales o anómalas.
  • Hemos agrupado todas las etiquetas distintas de normal bajo una sola categoría para simplificar el trabajo.
  • No hay una fecha y hora real por conexión, por lo que no podemos estudiar la evolución temporal.
  • Una conexión marcada como anómala no debe considerarse automáticamente un ataque confirmado. Estas limitaciones son importantes para no sacar conclusiones que vayan más allá de lo que los datos permiten.
